UNIT 1 — Introducing Text Control in SAP S/4HANA Sales

Sem exercícios — conteúdo conceitual.

Contexto

Textos em documentos de vendas não são campos livres: são objetos estruturados, com tipo, idioma, procedimento de determinação e (opcionalmente) estratégia de cópia automática entre documentos da cadeia.

Conceito

Tipo de Texto (Text Type) - É o pré-requisito para inserir um texto — a metáfora útil é "uma folha de papel em branco" esperando conteúdo - Definido por objeto de texto: VBBK (cabeçalho doc. vendas), VBBP (item), KNVV/KNA1 (cliente), etc. - Exemplos vistos no sistema: 0001 Form Header, 0002 Header Note 1, 0003 Header Note 2, Y001 Quotation Header Text

Procedimento de Determinação de Texto (Text Determination Procedure) - "Container" que agrupa os tipos de texto relevantes para um contexto específico - Transação: VOTXN (ou SPRO → SD → Basic Functions → Text Control → Set Up Text Determination)

Atribuição por nível:

Nível Procedimento atribuído a
Cabeçalho Tipo de documento de vendas / tipo de entrega / tipo de faturamento
Item Categoria de item (vendas ou entrega)
Faturamento Direto no tipo de faturamento (não existe categoria de item em faturamento)

Transferência automática de texto - Exige uma sequência de acesso vinculada ao tipo de texto dentro do procedimento - Sequência = estratégia de busca (objeto de texto + tipo de texto + idioma, opcionalmente parceiro/org. vendas) - Acessos são processados em ordem e são exclusivos: para no primeiro que encontrar

Regra crítica — cadeia de documentos:

Inquiry → Quotation → Order

Order NÃO puxa texto direto da Inquiry — só da Quotation
Quotation puxa da Inquiry
Order puxa da Quotation

Motivo: o acesso ao objeto VBBK/VBBP sempre se refere ao
        documento IMEDIATAMENTE ANTERIOR, nunca ao "avô"

Referenciar vs. Duplicar texto

Modo Comportamento
Referência Um único registro no banco; editar na fonte reflete em todos os documentos; edição manual no documento → passa a duplicar dali em diante
Duplicar Cópia independente; consome mais espaço; usar só quando funcionalmente necessário

✅ Diagnóstico AMS — Unit 1

  • "Texto da consulta não aparece no pedido" → antes de qualquer coisa, verificar se a configuração não está tentando pular um nível da cadeia. O pedido só lê da cotação.
  • "Alterei o texto na cotação e mudou no pedido também" → comportamento de referência (não duplicação); é configuração, não bug.

UNIT 2 — Setting Up Text Control (Exercício 1: Configure Text Control in Customizing)

Contexto

Business case: o setor de customer service precisa inserir um texto de cabeçalho específico nas cotações, e esse texto deve ser copiado automaticamente para o pedido de venda quando o pedido é criado com referência à cotação. O tipo de texto Y001 Quotation Header Text já existe no sistema e é utilizável em cotações — mas não está disponível nos pedidos do tipo ZA11.

Tarefa: criar procedimento de determinação de texto próprio, criar sequência de acesso que busque o texto na cotação, vincular ambos e atribuir ao tipo de documento ZA11. Depois, testar a propagação.

Conceito aplicado

A disponibilidade de um tipo de texto em um documento e a cópia automática desse texto são duas coisas independentes:

O que se quer O que configurar
Tipo de texto aparecer no documento Incluir o tipo no procedimento + atribuir procedimento ao doc. type
Texto ser copiado do predecessor Vincular uma access sequence ao tipo, dentro do procedimento

Se só o primeiro for feito, o tipo aparece na aba Texts mas sempre vazio (entrada manual). É exatamente o comportamento que o Y001 tem na cotação (procedimento Z1), onde a análise mostra 111 Access sequence does not exist.

Sequência executada

1. VOTXN → Sales Document / Header → Change
     → Text Determination Procedures
     → seleciona 01 → Copy As → chave 12, desc. "Header Text–Gr11"
     → "Choose the key from the allowed name space" (Enter) → copy all → Save

2. → Access sequences → New Entries
     → 9011 "ACESS SEQUENCE GR11" → Save
     → seleciona 9011 → Access sequence for Text IDs → New Entries
     → 010 / VBBK / Y001 / All Languages ✔ / Requirement 1 → Save

3. Volta até "Customizing Text Determination"
     → Texts → Generate access
     → mensagem de status: "Access generated" ✔

4. → Text Determination Procedures → seleciona 12
     → Text IDs in Procedure → New Entries
     → SeqNo 20 / ID Y001 / Access Seq. 9011 → Save
     (posicionado entre 0002 Header Note 1 e 0003 Header Note 2)

5. → Text Procedure Assignment (⚠ precisa estar em Change View)
     → linha ZA11 → campo TxtDe: 01 → 12 → Save

6. VA21 → cotação QT / C700-C11 / P605-111 / PPR0 300 EUR
     → Header details → aba Texts → texto no Y001 → Save

7. VA01 → ZA11 → Create with Reference → Quotation
     → aba Texts → duplo clique em Y001 → validar cópia → Save

🔧 Pegadinhas

1. Display View vs. Change View — o erro silencioso Navegar pela Dialog Structure sem passar pelo botão Change na tela raiz abre as views em modo exibição. O título da tela é o único indicador (Display View "..."). Os campos parecem editáveis mas não gravam nada. → Sempre conferir o título da tela antes de digitar.

2. Esquecer Texts → Generate access A sequência de acesso fica salva no customizing mas não funcional até ser gerada. Confirmação: mensagem de status "Access generated". → Regenerar sempre que a sequência for alterada.

3. Clique simples NÃO recarrega o conteúdo do texto Na aba Texts, clique simples apenas destaca a linha — a caixa de texto continua exibindo o conteúdo do tipo anterior. Só o duplo clique carrega o texto real daquele tipo. → Foi exatamente isso que mascarou a causa raiz por vários passos: o texto exibido pertencia ao Form Header, não ao Y001. → Sinal de que o tipo tem conteúdo: a coluna Lang. preenchida naquela linha.

4. Chave = 1 + ##, não ## Grupo 11 → procedimento 12. Erro de leitura aqui invalida o exercício inteiro (e, em exame SyBA, zera a tarefa mesmo com a configuração correta).

5. Namespace do cliente Ao copiar o procedimento aparece a mensagem "Choose the key from the allowed name space" — é apenas informativa nesse contexto de treinamento. Enter e segue.

6. Cotação com quantidade totalmente referenciada não aceita novo pedido Erro: "The reference has already been completely copied or rejected". É a Completion Rule B (Quotation → Order: item só fecha com quantidade TOTAL referenciada). A cotação 20000020 (qtd 1) foi integralmente consumida pelo pedido 400 e ficou Completed. → Para repetir o teste, criar nova cotação (foi o caso: 20000021).

7. Determinação de texto roda na CRIAÇÃO do documento O pedido 400 não se corrigiu sozinho depois que a origem foi ajustada. Não existe "reprocessar textos" nativo — diferente do botão Update de pricing.

✅ Diagnóstico AMS — Unit 2

O caso real desta prática (o mais valioso)

Sintoma: configuração de determinação de texto aparentemente 100% correta, tipo Y001 visível na aba Texts do pedido, mas sempre vazio.

Ferramenta: Análise de Determinação de Texto (Goto → Texts → Analysis na aba Texts do documento).

Leitura do log — os três códigos que resolvem o ticket:

Código Mensagem Significado Onde investigar
111 Access sequence does not exist Tipo de texto sem sequência de acesso → entrada manual por design Procedimento (VOTXN) — é assim que o Y001 se comporta na cotação (proc. Z1)
101 Requirement is not met: text could not be obtained Acesso abortado pela rotina de requisito (ABAP) Requisito no acesso / VOFM → Requirements → Text
110 Text does not exist Requisito atendido, acesso executado, mas a origem está vazia O documento predecessor — problema de DADO, não de config

Log obtido no pedido 400:

Text deter 12 TXT HEADER GR11
  Text ty Y001 Y001 Quotation header text    Access sequen 9011
    Nr  Object  ID    All  Req   Note
    010 VBBK    Y001   X   001   110 Text does not exist

Cadeia de eliminação de hipóteses executada:

# Hipótese Verificação Resultado
1 Procedimento errado atribuído ao ZA11 Log mostra 12 TXT HEADER GR11 ❌ Eliminada — atribuição correta
2 Y001 sem access sequence no procedimento Log mostra Access sequen 9011 ❌ Eliminada — vínculo correto
3 Access sequence não gerada Log executou o acesso 010 ❌ Eliminada — geração ok
4 Fluxo de documentos sem predecessor Environment → Document Flow: Quotation 20000020 → Order 400 ❌ Eliminada — fluxo íntegro
5 Conflito de idioma (Requirement 1) Idioma do BP C700-C11 = EN; texto salvo em EN; log deu 110, não 101 ❌ Eliminada — requisito passou
6 Texto gravado no tipo errado na origem Duplo clique tipo por tipo na cotação → texto estava em Form Header (0001) ✅ CAUSA RAIZ

Conclusão: o log 110 era absolutamente fiel. O sistema buscou VBBK / Y001 na cotação e corretamente não encontrou nada, porque o texto havia sido digitado no Form Header. Nenhuma linha de configuração estava errada.

Cenários de ticket AMS

Chamado típico Diagnóstico
"Configurei tudo certo e o texto não copia" Rodar Análise de Determinação de Texto primeiro. 110 → o problema é dado de origem, não config. Distinguir 110 de 101 economiza horas.
"Tipo de texto novo não aparece no pedido" Vínculo é em dois níveis: tipo→procedimento e procedimento→doc. type. Esquecer o segundo é o erro mais comum.
"Texto aparece mas sempre vazio" Tipo está no procedimento sem access sequence (111) — comportamento por design, entrada manual.
"Alterei o texto na origem, corrija os pedidos existentes" Não existe reprocessamento nativo. Ou entrada manual doc. por doc., ou programa em lote. Determinação roda na criação.
"Não consigo criar pedido a partir da cotação" Checklist: cotação Completed? quantidade totalmente referenciada? item rejeitado? Valid To expirado? copy control existe? → Fluxo de Documentos responde as duas primeiras.
"Alterei config e nada mudou" Verificar se a view estava em Change (não Display) e se o acesso foi regenerado.

🎯 Resumo executivo — Aprendizados-chave

  1. Disponibilidade ≠ cópia automática. Incluir um tipo de texto no procedimento o torna visível; só a access sequence o torna copiável. São duas configurações independentes, e confundi-las gera o ticket "aparece mas está vazio".

  2. Texto só copia do documento imediatamente anterior. Inquiry → Quotation → Order: o pedido lê da cotação, nunca da consulta. O objeto VBBK/VBBP sempre aponta para o predecessor direto.

  3. A Análise de Determinação de Texto é a PRIMEIRA ferramenta, não a última. Os códigos 101 / 110 / 111 particionam o espaço de causas antes de qualquer revisão manual de customizing.

  4. 110 Text does not exist significa "o dado não está lá", não "a config está errada". Foi a lição central desta prática: gastei o diagnóstico inteiro procurando erro de configuração quando o log já dizia que a configuração estava certa e a origem estava vazia.

  5. 101 vs. 110 é a distinção que separa júnior de sênior. 101 = requisito abortou o acesso (investigar VOFM/rotina). 110 = acesso rodou e não achou (investigar o documento predecessor).

  6. Clique simples não recarrega o conteúdo do texto na aba Texts. Só o duplo clique. A coluna Lang. preenchida é o indicador confiável de que o tipo tem conteúdo. Este detalhe de UI mascarou a causa raiz por vários passos.

  7. Sempre regenerar o acesso (Texts → Generate access) após criar ou alterar uma sequência. Sem isso a sequência existe mas não funciona. Confirmação: Access generated.

  8. Conferir Change View vs. Display View no título da tela. Navegar pela Dialog Structure sem clicar em Change abre em exibição, e a alteração se perde silenciosamente.

  9. Nomenclatura exata importa mais que a lógica. Chave = 1 + ## (grupo 11 → 12). Em exame SyBA, nome errado zera a tarefa mesmo com configuração perfeita.

  10. Completion Rule B tem efeito prático em teste. Cotação com quantidade totalmente referenciada fica Completed e recusa novo pedido ("The reference has already been completely copied or rejected"). Planejar quantidade maior, ou criar nova cotação a cada iteração de teste.

  11. Determinação de texto não é retroativa. Roda na criação do documento. Não há equivalente ao botão Update de pricing.

  12. Fluxo de Documentos (Environment → Document Flow) valida a integridade da cadeia em um olhar — predecessor, quantidade referenciada, status. Elimina hipóteses rápido.
