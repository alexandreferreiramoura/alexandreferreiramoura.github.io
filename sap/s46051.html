🔧 Pegadinhas de navegação (Fiori vs. GUI)

  • Incoterms e Payment Terms não estão na aba Sales — ficam em Billing Document (bloco "Terms of Delivery and Payment").
  • Division e Material Pricing Group ficam no item (aba Sales B), não no cabeçalho.
  • Plant / Shipping Point / Route / datas aparecem todos juntos na visão All Items — atalho muito mais rápido que abrir cada aba do item.
  • Não confundir Material Group (L001) com Material Pricing Group (Normal) — campos distintos, ambos na Sales B.

✅ Diagnóstico AMS

O conjunto Sales Office/Employee + Plant + Route + Incoterms + Payment Terms é o kit de diagnóstico padrão para chamados do tipo "por que o pedido do cliente X saiu com prazo/rota/condição diferente do esperado?". Todos derivam do cadastro do parceiro + Sales Area, e só são sobrescritos manualmente em exceções. Se o valor está errado no pedido, a causa raiz quase sempre está no BP, não no pedido.

UNIT 2 — Working with Quantity Contracts (Exercício 2)

Conceito

Quantity Contract (KM) = acordo de que o cliente comprará uma quantidade de um produto num período. O contrato tem quantidade e preço, mas não tem cronograma de entregas. O cliente cumpre o contrato criando release orders (call-offs) que referenciam o contrato — o sistema abate automaticamente a quantidade liberada.

Criação (Manage Sales Contracts)

Campo Valor
Order type KM
Sales Area 1010 / 10 / 00
Sold-to Party C605-A34
Cust. Reference 34KM
Description Quantity contract 34
Valid to hoje + 6 meses
Material P605-334
Target Quantity 50

Net Value inicial: 75.000,00 EUR (50 × 1.500) Após K007 20% (Item Conditions): 60.000,00 EUR

Evolução do consumo do contrato

Passo Pedido Qtd Método de criação Order Qty acumulada

4 436 15 VA01 → Create with Reference → aba Contract 25

🔧 Três descobertas importantes desta unit

1. Pedido sem referência não consome saldo nem herda condições

O pedido 438 (5 PC) foi salvo após cancelar o pop-up de outline agreement. Resultado: - Order Quantity do contrato permaneceu em 30 (não subiu) - Desconto K007 não foi aplicado → Net Value = 7.500 EUR (5 × 1.500, preço cheio)

Por quê o desconto não veio: o K007 foi inserido manualmente no item do contrato, não existe como registro de condição mestre (VK13) do cliente. Sem referência ao contrato, não há de onde herdar.

2. Assign Contract → Item falha em tipos de documento sem Copy Control

Tentativa de vincular retroativamente o pedido 438 (tipo ZA34):

Manage Sales Orders → 438 → Change
→ Menu → Edit → Assign Contract → Item
→ Contract: 400000016 → Assign

Erro recebido: Copying from sales document type CQ to CQ is not supported

Causa raiz: falta rota de Copy Control (VTAA) configurada envolvendo o tipo ZA34. Funciona com tipo OR (padrão), mas não com o tipo customizado.

3. Contrato esgotado deixa de ser oferecido — silenciosamente

A partir do momento em que o contrato atingiu 50/50 (Completed), o pop-up "Open outline agreements for item" simplesmente parou de aparecer, e os pedidos passaram a nascer sem o desconto. Nenhuma mensagem de erro ou aviso foi emitida.

Isso explica os pedidos 440/441/442: não foi erro de digitação nem de cache — o contrato já estava esgotado.

Customizing SPRO (Passo 11)

SPRO → Sales and Distribution → Sales → Sales Documents
     → Sales Document Header → Define Sales Document Types
→ Position: ZA34 → Details → seção "Transaction flow"
Campo Valor definido Significado
Outline agrmt mess. F Check at item level and branch directly into selection list
Quotation messages F Idem, para cotações em aberto

Limitação confirmada: a config F só surte efeito enquanto existir contrato em aberto para o material. Contrato Completed → nenhuma verificação é disparada.

Validação final (Passo 14)

Manage Sales Contracts → 400000016 → Create Subsequent Order → OR → OK

Mensagem: The reference has already been completely copied or rejected

✅ Diagnóstico AMS — Quantity Contracts

Cenário 1 — "o desconto do contrato parou de aplicar" Checklist de causa raiz, em ordem: 1. O contrato está esgotado (Order Qty = Target Qty)? → status Completed 2. O contrato está vencido (Valid to no passado)? 3. O pedido foi criado com referência ao contrato? (verificar Document Flow ou ausência das condições) 4. A condição está no contrato ou é registro mestre? (VK13)

Cenário 2 — "não consigo vincular o pedido ao contrato depois de criado" → Verificar Copy Control (VTAA) entre o tipo de pedido e o tipo de contrato. Tipos Z* customizados frequentemente não têm a rota configurada.

Cenário 3 — "o vendedor esquece de referenciar o contrato" → Config Outline agrmt mess. = F no tipo de documento força a lista de seleção. Reduz drasticamente o volume desse ticket, mas não impede completamente (o usuário ainda pode cancelar o pop-up).

UNIT 3 — Work with Value Contracts (Exercício 3)

Conceito

Value Contract (WK1) = acordo por valor total (target value), não por quantidade. O cliente pode comprar qualquer produto permitido até esgotar o valor. Os produtos permitidos são restringidos por assortment module e/ou product hierarchy.

⚠️ Este exercício é executado no SAP GUI back-end (VA41, VA42, VA43, VA01, WSV2, SPRO), não no Fiori.

Restrição de produtos: Assortment Module (Passos 8–11)

Conceito: para impedir que produtos fora do escopo sejam vendidos via value contract, atribui-se ao contrato uma product hierarchy e/ou um value contract – assortment module. A atribuição restringe automaticamente todos os release orders daquele contrato.

Criação (WSV2):

Logistics → SD → Master Data → Products
         → Value Contract - Assortment Module → WSV2 Create
→ Tela inicial: SEM entrada, clicar direto em "Items"
→ Description: VC module 34
→ Materiais: P605-134, P605-234, P605-334
→ Valid-to: 31.12.2027
→ Save

Número gerado: 10000000107

Atribuição (VA42): campo Assortment Module no item do contrato → 10000000107 → Save

Efeito na criação do release order: botão Expand assort. passa a listar apenas os 3 materiais permitidos. O P605-734 (Max-Bike), vendido no pedido 445 antes da restrição, deixa de aparecer.

🔧 Controle "soft" ao exceder o target value (Passo 15)

Pop-up recebido ao salvar o pedido 448:

Value contract release
  Target value of value contract has been exceeded!
  Value contract: 0040000017, Item: 000010
  Difference rate: 2.140,00 EUR
  Do you still wish to save the document or continue to edit?
  [ Save ]  [ Edit ]  [ Cancel ]

Ponto crítico: o sistema oferece o botão Save. Este é um controle de aviso, não de bloqueio — comportamento definido por Contract Release Ctrl = A na item category WKN.

Contraste importante: um credit block é controle "hard" (impede o salvamento / bloqueia a entrega). Excesso de target value em value contract é "soft" (avisa e deixa passar). Confundir os dois é erro comum em análise de chamado.

✅ Diagnóstico AMS — Value Contracts

Cenário 1 — "vendemos acima do valor contratado e o sistema deixou" → Comportamento esperado com Contract Release Ctrl = A. Se o negócio exige bloqueio, é mudança de customizing na item category WKN, não bug.

Cenário 2 — "o vendedor conseguiu vender produto fora do escopo do contrato" → Falta assortment module ou product hierarchy atribuída ao contrato. Verificar campo Assortment Module no item (VA43).

Cenário 3 — "não consigo copiar o material do contrato para o pedido" → Comportamento esperado: WKM1 é material de controle. Verificar Cont. Item Copy Mode (VTAA, Target OR / Source WK1, item WKN).

Cenário 4 — "cliente reclama que a filial não consegue fazer pedido contra o contrato" → Verificar parceiros AA/AW no header do contrato (VA42 → Goto → Header → Partner) e o procedimento KAB.

UNIT 3 — Maintain Contract Data in a Sales Document (Exercício 4)

Conceito

Contratos de aluguel (MV) e de serviço usam um contract profile atribuído no customizing do tipo de documento. Esse profile preenche automaticamente todas as regras de vigência, duração, renovação e cancelamento — nada é digitado pelo usuário.

Campo Valor

Sales Area 1010 / 10 / 00
Sold-to party C605-B34
Cust Reference 34MV

Contrato criado: 40000018

Dados de contrato preenchidos automaticamente

Goto → Header → Contract data

Campo Valor Regra

Val.Period.Category 02 1 year

Campos de Termination vazios = nenhum cancelamento ativo. Não é erro nem pendência.

✅ Diagnóstico AMS — Rental / Service Contracts

O par Action + Action date é o gatilho de renovação. Com 0004 Create sales act. e regra 19 (End of Contract − 1 Month), o sistema gera automaticamente uma atividade de vendas 1 mês antes do vencimento, para o vendedor contatar o cliente.

Cenário real: "o contrato do cliente venceu e ninguém foi avisado" → Causa raiz típica: campo Action vazio no contract profile, ou regra de Action date mal configurada. Verificar o contract profile atribuído ao tipo de documento no SPRO.

Cenário real: "cancelamos o contrato mas continua ativo" → Verificar Cancellation Procedure. Com 0001, o cancelamento só produz efeito no fim do período de validade — não é imediato. Cliente muitas vezes espera efeito imediato.

🎯 Resumo executivo — 8 aprendizados para levar à prova

# Aprendizado
1 Pedido sem referência ao contrato não consome saldo nem herda condições. Condição inserida manualmente no contrato não existe como registro mestre.
2 Contrato Completed deixa de ser oferecido silenciosamente — sem erro, sem aviso. Causa raiz oculta de "o desconto parou de funcionar".
3 Assign Contract → Item depende de rota em Copy Control (VTAA). Tipos Z* customizados frequentemente não têm.
4 Outline agrmt mess. = F (Define Sales Document Types) força a lista de seleção — mas só com contrato em aberto.
5 Item Category de value contract vem do usage VCTR → WKN. Material WKM1 é fictício e não copiável (Cont. Item Copy Mode = A).
6 Excesso de target value é controle soft (Contract Release Ctrl = A): avisa e permite salvar. ≠ credit block (hard).
7 Funções AA/AW com Source C buscam parceiro no contrato, não no BP — habilita release por terceiros autorizados (procedimento KAB).
8 Contract profile (MV) preenche start/end/duration/cancelamento automaticamente. Par Action + Action date é o gatilho de renovação.
