Exercício 1 — Access, Explore, and Personalize the SAP Fiori Launchpad

Contexto

Criar um usuário de teste, validar acesso ao Fiori Launchpad e personalizar a página My Home (seções customizadas, tiles, reposicionamento).

Sequência executada

1. SU01 → cria S4C_USER_61 (senha inicial ••••••)
2. Roles tab → Z_FIORI_FOUNDATION_USER, Z_BR_S4C03_USER_ROLE, Z_S4C02 → Save
3. Login de teste com S4C_USER_61 → troca de senha forçada → ••••••
4. Sign Out do usuário de teste; retorno às credenciais originais usuário de treinamento (grupo 61)

🔧 Pegadinha — passos 5–15 não aplicáveis nesta versão do sistema

O roteiro oficial descreve criação de seções nomeadas (My Favorites, Custom Logic Apps) via menu "Edit Current Page" → +Add Section, com reposicionamento por drag-and-drop e exclusão seletiva.

Nesta versão do sistema, o menu do usuário não tem mais "Edit Current Page" — foi substituído por "My Home Settings", que abre um painel de Layout com apenas 4 blocos fixos e não-renomeáveis: To-Dos, News and Pages, Apps, Insights Tiles and Cards. Não há suporte a criar seções customizadas livres nem a excluir blocos — só habilitar/desabilitar visibilidade e reordenar via drag-and-drop.

Causa raiz: mudança de release do Fiori Launchpad (experiência "Horizon"/My Home reestruturada) posterior à criação do material de treinamento. Não é erro de execução.

Decisão tomada: passos 5–15 pulados, documentados como divergência de versão. Passos 1–4 e 16 (criação/teste de usuário, fechamento) executados normalmente.

✅ Diagnóstico AMS

  • "A documentação de treinamento não bate com o sistema produtivo" → identificar mudança de release/FPS antes de tentar forçar passos obsoletos; nunca insistir em um caminho de UI que não existe mais.
  • Personalização de launchpad é armazenada por camada (USER vs. admin/shared) — distinguir seção customizável do usuário (sempre pode ser removida) de seção admin-defined/predelivered (só pode ser resetada, nunca deletada) continua válido mesmo com a UI nova.

Exercício 3 — Access the Cloud Integration Automation Service (CIAS)

Contexto

Exercício de consulta/leitura (sem gravação no sistema) no SAP Activate Roadmap Viewer, revisando os requisitos técnicos do serviço CIAS.

🔧 Pegadinha — portal migrado de endereço

O link antigo do roteiro (go.support.sap.com/roadmapviewer, acesso anônimo) retorna HTTP 404 — descontinuado. Acesso atual exige login com SAP Universal ID, via SAP for Me: https://me.sap.com/roadmapviewer.

Nomenclatura de roadmap também mudou: "RISE with SAP S/4HANA Cloud Private Edition" foi renomeado para "SAP Cloud ERP Private". Caminho de navegação atualizado:

me.sap.com/roadmapviewer → Explorar todos os roadmaps
  → aba "Cloud ERP" → seção "SAP Cloud ERP Private (4)"
    → "SAP Activate para SAP Cloud ERP Private - Nova implementação"
      → Conteúdo → Preparar → Acesso inicial ao sistema para SAP Business Technology Platform
        → Assinar o serviço Cloud Integration Automation no SAP BTP

Conceito

O CIAS entrega um workflow guiado no BTP para configurar integrações entre S/4HANA Cloud Private Edition e outras soluções SAP em nuvem.

Pré-requisitos: - Subconta BTP Cloud Foundry num data center suportado (ou conta SAP Cloud Integration) - Instâncias de sistema licenciadas dentro do escopo do serviço

Regra de assinatura — o ponto central: | Cenário | Ação | |---|---| | Cliente já tem tenant SAP Cloud ALM solicitado | CIAS é assinado automaticamente na mesma subconta BTP — só verificar provisionamento | | Cloud ALM veio de outra assinatura, ou quer instância CIAS separada | Assinar manualmente na subconta BTP, seguindo o acelerador oficial |

✅ Diagnóstico AMS

  • "Portal/link de documentação não abre" → segundo caso do dia do mesmo padrão do Ex.1: buscar pelo nome atual da ferramenta em vez de confiar em link salvo, pois portais SAP migram de endereço com frequência.
  • "Por que o CIAS não está disponível pro meu cliente?" → verificar primeiro se o tenant do Cloud ALM já foi solicitado; é ele que dispara o provisionamento automático do CIAS.

Exercício 4 — Adding a Custom Field

Contexto

Criar um campo customizado via app Fiori Custom Fields (via extensibilidade in-app, sem tocar em ABAP) e habilitá-lo em UIs/reports relevantes.

Sequência executada

App Custom Fields → (+) Create
  Business Context: Bank Account Master Data
  Label: Custom Field S4C-61
  Identifier: (auto) ZZ1_CustomFieldS4C61
  Tooltip: (auto) Custom Field S4C-61
  Type: Text | Length: 20
→ Create and Edit

Aba User Interfaces → Enable Usage em:
  C_BANKACCOUNTTP, FCLM_BAM_ACCOUNTWD_SRV → propagou para os 4 data sources da árvore
  (todos passaram a Enabled com um clique cada, sem travamento)

C_BankAccountTPType → detalhe → Search Relevance → ON

→ Save → Publish

Resultado esperado (conforme roteiro) — confirmado:

Data Source Search Relevance Field Usage
Bank Account Administrative Data (I_BANKACCOUNTTP / C_BANKACCOUNTTP) — / Enabled Enabled
Bank Account BO active and draft (C_BankAccountTPType) Enabled Enabled
Manage Bank Account (FCLM_BAM_ACCOUNTWD_SRV) — Enabled

🔧 Pegadinha — identificador ganha prefixo automático

O sistema prefixa automaticamente o identifier com ZZ1_ (não Z/Y como em ABAP clássico) — indicativo visual de que o campo nasceu via extensibilidade in-app "clean core", não via desenvolvimento direto.

✅ Diagnóstico AMS

  • Custom Fields é a via recomendada pela SAP para extensibilidade clean core — nunca sugerir ABAP direto num sistema Cloud Private Edition gerenciado para esse tipo de necessidade.
  • "Criei o campo mas não aparece na tela" → 90% das vezes falta Publish (campo fica em rascunho/"Publishing..." indefinidamente sem essa ação).
  • "Criei o campo mas não consigo buscar por ele" → falta de Search Relevance, não bug — campo existe mas não está indexado para filtro/busca.

Exercício 5 — Migrate Legacy Data

Contexto

Ciclo completo de migração de dados legados via Migrate Your Data (staging tables): criar projeto, copiar objeto de migração Bank, baixar template, popular dados, subir template, preparar staging, confirmar mapeamentos, simular e migrar, validar resultado.

Task 1 — Identificação do objeto (consulta rápida, sem navegação no Help Portal)

  • Transação SAP GUI de validação: FI03 (Display Bank)
  • App Fiori de validação: Manage Banks

Sequência executada — Tasks 2 a 6

Task 2 — Criar projeto
Migrate Your Data → Create → Migrate Data Using Staging Tables
  Name: Migrate Data Bank 61
  Database Connection: Local SAP S/4HANA Database Schema
  → Step 2 → Local Package ($TMP) → Step 3
  → marcar objeto Bank → mover (>) → Review → Create Project

Task 3 — Download template
Selecionar objeto Bank → Download Template (dropdown no header) → Download XML File

Task 4 — Popular dados (Excel)
Bank Master tab:
  CN | 960161 | ICBC, China | ChenHui RD, 1001 | Shanghai
  CN | 960261 | ICBC, China | Main RD, 3002    | Shanghai
  CN | 960361 | ICBC, China | PuDong RD, 1003  | Shanghai
Save As → Source Data for Bank_61.xml (manter formato XML)

Task 5 — Upload + preparação + mapeamento + simulação + migração
Upload File → Source Data for Bank_61.xml
  → status: "Data Successfully Transferred to Staging Tables"
→ Prepare → Consistency Check ON → Prepare Staging Tables → Monitoring → Completed
→ Mapping Tasks → confirmar Country/Region Key + Bank Key (via lista, sem entrar item a item)
  → contadores: To Be Confirmed 0, Confirmed 2
→ Migrate → All Instances → Start Migration
  → Migration Progress: 100%, Successful: 3, Errors: 0

Task 6 — Validação
Manage Banks - Master Data → filtro Bank Country/Region: CN → Go
  → 3 registros confirmados: 960161, 960261, 960361 (ICBC, China), endereços corretos

🔧 Pegadinhas identificadas

  1. Botão "Step 2" fora da área visível — não era travamento algum; o botão renderiza abaixo de um dropdown vazio no formulário e ficou coberto por um tooltip de preview do navegador (hover sobre aba). Antes de reportar "botão não aparece", sempre: (a) fechar popups/tooltips do navegador, (b) rolar a tela inteira.
  2. Mapping Tasks simplificado nesta versão — o roteiro descreve confirmar cada mapeamento individualmente (entrar no detalhe, marcar, confirmar, voltar). Nesta versão do app, dá pra marcar a checkbox de cada mapping direto na lista e clicar Confirm no header, sem entrar em cada um. Mais rápido que o documentado.
  3. Coluna Simulation ficou com "Successful: 0" mesmo após migração 100% bem-sucedida — não bloqueante; provavelmente o contador de Simulation só reflete se o Simulate formal foi disparado separadamente antes do Migrate, e neste ciclo a migração seguiu direto sem esse passo isolado ter sido contabilizado à parte.

✅ Diagnóstico AMS

  • Consistency Check na preparação do staging valida integridade referencial (chaves duplicadas, campos obrigatórios ausentes) antes do mapeamento — pular essa checagem é causa comum de erro só descoberto tarde, na simulação, mais caro de corrigir.
  • Simulate antes de Migrate é dry-run que evita gravação parcial de dados inválidos — prática de risco em projeto real é pular direto pro Migrate.
  • Sempre validar resultado final via app Fiori (Manage Banks) e, se aplicável, também via transação GUI (FI03) — o roteiro reforça que ambos os caminhos de validação existem e podem ser cobrados separadamente em cenário de suporte.

🎯 Resumo executivo — Aprendizados-chave

  1. Documentação de treinamento envelhece mais rápido que o sistema. Três exercícios diferentes (Ex.1 seções do launchpad, Ex.3 link do Roadmap Viewer, Ex.5 confirmação de mappings) mostraram UI/portal reestruturados desde a escrita do roteiro. O hábito correto é sempre validar a versão atual e adaptar, nunca insistir num caminho que sumiu.

  2. "Travado" quase sempre é "fora da tela". O caso do botão Step 2 (Ex.5) — coberto por um tooltip do navegador e abaixo do viewport — reforça: antes de escalar como bug, sempre limpar popups e rolar a página inteira.

  3. Custom Fields (Ex.4) é a via clean core para extensibilidade em campo. Prefixo automático ZZ1_ sinaliza origem via extensibilidade in-app. Nunca recomendar ABAP direto num sistema Cloud Private Edition gerenciado para essa necessidade.

  4. Publish ≠ Save em Custom Fields. Campo salvo sem Publish fica em "Publishing..." — visível na lista, mas não ativo em produção. Causa raiz clássica de "criei mas não aparece".

  5. CIAS não se assina no vácuo — depende do Cloud ALM. Se o cliente não solicitou o tenant do SAP Cloud ALM, o CIAS não aparece provisionado automaticamente. Pergunta de triagem #1 em ticket de "CIAS indisponível".

  6. Migração de dados tem ciclo obrigatório em 6 etapas (Task 1 a 6 do Ex.5): identificar objeto → criar projeto → baixar template → popular → subir/preparar/mapear/simular/migrar → validar. Pular Consistency Check ou Simulate é risco real, não só formalidade do roteiro.

  7. Company (Ex.2) é customizing, sempre transportável. Diferente de master data. Confundir as duas categorias trava saves em ambiente real por falta de developer key/request.

  8. Nomenclatura com sufixo ##/grupo continua sendo o ponto de maior risco de erro em qualquer exercício — em exame SyBA, nome incorreto zera a tarefa mesmo com configuração tecnicamente perfeita.
